# 零页 · 学生 Builder 个人主页

「零页」的最小静态主页，面向中文用户，记录一个大一学生用 AI 和代码构建产品的过程。采用已选的「零号刊」方向：暖白纸面、炭黑汉字零、电光蓝像素和章节页码。

## MVP 内容

- 00 首页：个人定位、品牌主视觉和两个章节入口。
- 01 正在构建：智能收纳助手的真实已有版本截图，其他工具与开发实践，以及可展开的过程和限制。
- 02 构建日志：真实发布记录按日期倒序展示；当前没有已发布记录，显示空状态。
- 03 关于：学生身份、学习与构建方式，以及 X / GitHub 联系入口。

四个入口目前都是同一页的锚点。桌面与手机共用内容，导航随滚动和锚点切换高亮。关闭 JavaScript 后，正文、锚点和折叠详情仍可使用。

## 本地运行

```powershell
npm run dev
```

打开 http://127.0.0.1:4173。项目使用 Node.js 20+ 内置模块，没有运行时 npm 依赖。

## 验证与构建

```powershell
npm test
npm run build
```

- 测试覆盖品牌、日志空状态、稳定编号与排序、转义、页面底部的导航高亮，以及构建资源与章节链接。
- 构建产物位于 `dist/`，使用相对资源地址，可部署在站点子路径。
- 浏览器视觉与交互证据见 `design-qa.md`，截图保存在 `.qa/`。
- 本地构建不会推送或发布网站。

## 内容维护

资料集中在 `src/site-data.mjs`：

- `hero`、`about`：首屏与关于文案。
- `brand.image`、`brand.alt`：品牌素材与替代文本。
- `projects`：项目摘要、已有状态、真实截图、过程、限制和入口。
- `xUrl` / `xHandle`：当前使用 https://x.com/page0lab / @page0lab。
- `productionUrl`：分享元数据与 canonical 的正式地址。

日志只添加真实已发布的内容。记录格式如下，编号发布后保持稳定：

```js
{
  id: "B001",
  date: "2026-10-08",
  title: "真实记录的标题",
  summary: "本次尝试、取舍或结论。",
  url: "", // 有文章地址时再填写；留空时显示纯文字。
}
```

没有真实下载或文章地址时，项目对应链接保持空字符串，页面不会生成空按钮。记录数组为空时仍保留 02 章节与导航，不创建示例文章。

品牌素材位于 `public/assets/lingye-zero.png`，同时用于首屏、导航、favicon 与分享图片。旧头像保留在源码目录，构建时排除。项目截图沿用已有真实资料，版本状态不会因网站重构自动升级。

## 部署边界

仓库原 GitHub Pages 地址为 https://xulimeng2022.github.io/seqriver-portfolio/，当前 MVP 沿用它作为正式 URL 配置；本次沿用现有仓库与网址发布，不重命名仓库或变更域名。

`docs/` 是 GitHub Pages 部署目录，使用 `npm run build:pages` 更新静态产物；推送到 `main` 后由 GitHub Pages 构建上线。Netlify 则使用现有 `netlify.toml`，发布目录为 `dist/`。
